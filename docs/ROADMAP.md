## 三、设计方案

### 3.1 三个想法串成一条流水线

```
        设置（默认路径 / 开关）
                 ↓
   扫描 → 指纹比对 → 发现全新工程
                 ↓
        自动解包（可选开关）
                 ↓
        自动上传（可选开关）→ 上传成功 → 删除本地副本
```

现有代码只有「解包任务」概念。要支持这条流水线，需要引入
**「扫描任务」** —— 扫描本身也可能很慢（几百个工程目录），
而且和「解包任务」是先后关系，不是并列关系。

### 3.2 配置文件拆分

现状 `data/scan_history.json` 混了「当前配置」和「用过的路径」。
拆成两个，理由：配置是**用户会改的当前状态**，历史是**只增不减的行为记录**。

```
data/settings.json      ← 配置（路径、开关、上传目标）
data/secrets.json       ← 凭证（AK/SK、密码），已 gitignore
data/index.json         ← 已处理工程的索引（指纹 + 解包/上传状态）
data/scan_history.json  ← 用过的目录列表
```

> ⚠️ **凭证绝不能写进 `settings.json`** —— 那个文件可能被人看到或分享。
> `secrets.json` 同样要加进 `.gitignore`（`data/` 整个目录已经在 ignore 列表里）。

### 3.3 配置项

```jsonc
{
  // Wallpaper Engine 素材目录（可多个，如不同游戏）
  "wallpaper_dirs": ["D:\\Program Files (x86)\\Steam\\steamapps\\workshop\\content\\431960"],
  "recursive": true,

  "auto_extract": false,      // 扫描发现新工程后自动解包
  "auto_upload": false,       // 解包完成后自动上传
  "delete_local_after_upload": true,  // 上传成功后删本地副本（决策 4）

  "output_dir": "out",        // 解包输出根目录

  "upload_targets": [
    {
      "name": "阿里云 OSS",
      "type": "s3",           // s3 | webdav
      "bucket": "my-wallpapers",
      "endpoint": "oss-cn-hangzhou.aliyuncs.com",
      "prefix": "wallpaper-engine/",
      "secret_ref": "oss_main"   // 指向 secrets.json 里的键名，不存明文
    },
    {
      "name": "坚果云",
      "type": "webdav",
      "base_url": "https://dav.jianguoyun.com/dav/",
      "remote_dir": "/wallpapers",
      "secret_ref": "jianguoyun"
    }
  ]
}
```

### 3.4 「新增工程」的判定

Wallpaper Engine 的工程目录名是 **Steam Workshop ID**（如 `1289347078`）。
目录名永不变，但内容会被作者更新。按决策 1，**只处理从未见过的 ID**。

`data/index.json`：

```jsonc
{
  "1289347078": {
    "first_seen": "2026-11-02T10:00:00",
    "extracted_at": "2026-11-02T10:00:05",
    "uploaded_at": null,
    "upload_status": "pending",   // pending | uploading | done | failed
    "pkg_size": 12345678,
    "pkg_mtime": 1699999999
  }
}
```

`pkg_size` / `pkg_mtime` 保留下来是为了**将来**想支持「作者更新后重新解包」
时不用改结构（决策 1 目前不用它们）。

#### ⚠️ 首次启用的坑

本机已经扫描过 **495 个真实工程**。如果第一次开启「自动解包」，
它们**全部**会被判定为「全新」，一次性触发 495 个解包任务
（几百 GB、几十分钟）。

**实现时必须提供「初始化索引」的入口** —— 把当前已有的工程批量标记为
「已见」而不解包。首次启用自动化的标准流程应该是：

1. 先开启自动扫描（不开自动解包），扫一遍建立索引
2. 确认数量对得上（495）
3. 再开启自动解包

### 3.5 上传

**上传内容**：只有 `media/` 下的图片和视频（决策 3）。不上传原始资源、
不上传 `.tex`、不上传目录结构 —— 你要的是能直接看的壁纸。

**路径映射**：云端路径 = `prefix/` + `<工程名>/` + `<媒体文件名>`。
保留工程名是为了避免同名文件互相覆盖。

**S3 兼容**能覆盖：AWS S3、阿里云 OSS、腾讯云 COS、Cloudflare R2、
MinIO、Backblaze B2。一套 boto3 代码通吃。

**WebDAV** 能覆盖：坚果云、Nextcloud、自建。

**刻意不做**：百度网盘 / 阿里云盘 / Google Drive 的直连上传。
国内网盘没有官方开放 API，逆向有封号风险；Google Drive 的 OAuth
授权流程对这个工具来说太重。如果以后真需要，走它们的「同步文件夹」
间接实现更稳。

#### 上传后的删除（决策 4 —— 风险最高的一条）

自动删本地副本是这批功能里**唯一有不可逆风险**的。实现时必须加这些护栏：

1. **先验证再删**：S3 侧比对对象大小（或 ETag），WebDAV 侧比对
   `Content-Length`。校验不通过 → 保留本地文件 + 标记失败
2. **只删自己产生的文件**：只删 `out/` 下本工具解包出来的内容，
   **绝不触碰** Steam 原始目录里的任何东西（这条红线现有代码已经保证）
3. **单工程可覆盖**：每个工程有「保留本地副本」的开关，勾选后永不自动删
4. **支持 dry-run**：配置里加 `delete_local_after_upload: false` 做全局关闭
5. **失败绝不删**：上传失败、超时、校验不通过 —— 一律保留

如果以后觉得「立刻删」太激进，可以升级成**本地缓存淘汰**：
上传后不立刻删，而是按总容量上限（可配）LRU 淘汰。
功能上一样是省磁盘，但更不容易误删。

### 3.6 未来可能加的接口

```
GET    /api/settings              读取配置
PUT    /api/settings              保存配置
POST   /api/settings/test         测试上传目标连通性（不真的传文件）
POST   /api/auto-scan             启动扫描流水线，返回 scan_task_id
GET    /api/auto-scan/{id}        扫描/流水线进度
POST   /api/auto-scan/{id}/cancel 中断
POST   /api/upload/{project_id}   手动上传某个工程
GET    /api/upload-targets        已配置的上传目标
DELETE /api/upload-targets/{name} 删除上传目标
```

### 3.7 分阶段实施建议

按依赖顺序，每阶段都能独立交付：

| 阶段 | 内容 | 依赖 |
|---|---|---|
| **一** | 配置存储 + 设置界面 + 默认路径 | 无 |
| **二** | 扫描指纹索引 + 自动解包 + 初始化索引入口 | 阶段一 |
| **三** | S3 兼容上传 | 阶段一、二 |
| **四** | WebDAV 上传 | 阶段三（共用上传抽象层） |
| **五** | 上传后自动删除 + 安全护栏 | 阶段三/四 |
| **六** | 扫描流水线统一任务视图（复用左侧栏） | 阶段二 |

阶段三和四应该**先抽出统一的 `Uploader` 抽象**，再加两个具体实现，
否则 WebDAV 会把 S3 的代码结构带偏。

### 3.8 风险清单

| 风险 | 缓解 |
|---|---|
| 自动删除误删 | 校验后删除 + 只删 out/ + 单工程覆盖 + dry-run |
| 首次启用触发 495 个任务 | 初始化索引入口 + 建议先只开扫描 |
| 凭证泄漏 | `secrets.json` + gitignore + 配置文件只存引用名 |
| 大文件上传中断 | 分片上传 + 断点续传 + 失败重试 |
| 自动上传拖慢解包 | 上传在独立线程/任务里，不阻塞解包 |
| 扫描目录消失（Steam 卸载） | 记录历史里标记失效，不自动删除历史记录 |
